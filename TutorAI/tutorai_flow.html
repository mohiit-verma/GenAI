End‑to‑End Flow

This page shows how data moves through the system: utilities → indexing → retrieval → prompt assembly → generation → guardrails, including conditions for chit‑chat and similarity cutoff.

High‑Level Data Flow

Legend Blue/green lines show data flow between stages. Boxes represent major components.

Key Conditions (Routing & Guardrails)

Intent
Chit‑chat → bypass RAG, no citations. Book_QA → retrieve + require citations.
Similarity cutoff
If all blocks are filtered out, send empty context → model must refuse (no forced page numbers).
Guardrail
For Book_QA answers, if the model omits citations, append (p. N) from retrieved blocks or parse from answer.
History
ConversationBufferMemory injects prior messages into the prompt for continuity.

Success Criteria

  • All factual answers include page citations for Book_QA.
  • Chit‑chat/meta answers have no citations.
  • When context is empty (or cutoff removes all), answer is a clear refusal.

Prompt Skeleton

<system>
You are TutorAI. Answer only from the provided book context.
If answer not in context, refuse. Include page citations like (p. N).
{system_description}

<history>
...prior user/assistant turns...

<user>
User query:
{user_query}

Book context (use ONLY this; cite every claim):
{context}

Guidelines:
{guidelines}
</user>
Placeholders are resolved at runtime. Context is constructed from retrieved chunks with known page numbers.

  "citation": "(p. 42)"

  "retrieved_context": [...],
  "history_len": 7
}

Typical Paths

Book_QA (happy path)

  1. User asks a question about charts.
  2. Intent: book_qa → retrieve K chunks → cutoff.
  3. Prompt assembled → LLM generates.
  4. Guardrail ensures citations; answer returned with page list.

Chit‑Chat

  1. User says "hi" → intent: chit‑chat.
  2. Bypass retrieval & guardrail citations → short capability reply.

No Relevant Context

  1. Query outside the book, or cutoff too strict.
  2. Context empty → model returns refusal (no page numbers).
